## 🧠 What I Should Practice

For every problem, try to think through:

1. **Requirements**

   * What should the system do?
   * What is out of scope?

2. **Actors / Entities**

   * Who interacts with the system?
   * What objects/entities exist?

3. **Use Cases**

   * What are the main operations?

4. **Core Design**

   * Classes / objects
   * Relationships
   * Interfaces
   * Responsibilities

5. **Data**

   * What needs to be stored?
   * Where should it live?

6. **System Behavior**

   * What happens when something changes?
   * What happens when something fails?

7. **Edge Cases**

   * Invalid input
   * Resource unavailable
   * Concurrent operations
   * Failures

8. **Trade-offs**

   * Why did I choose this design?
   * What alternatives exist?

9. **Scalability**

   * What breaks when the system gets bigger?
   * How would I change the design?

10. **Communication**

    * Can I explain the design clearly without getting lost in implementation details?

---

## 🎯 Goal

Don't memorize solutions.

The goal is to develop the ability to look at an unfamiliar problem and naturally ask:

> **"What are the components, how do they interact, and what happens when things go wrong?"**
